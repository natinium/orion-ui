## Usage

```tsx
import { CalendarScheduler } from '@/components/ui/calendar-scheduler'
```

```tsx
<CalendarScheduler
  events={[
    {
      id: 'standup',
      title: 'Standup',
      start: '2026-11-16 09:00',
      end: '2026-11-16 09:15',
      color: '#0ea5e9',
    },
  ]}
  defaultView="month"
  onEventMove={(eventId, newStart) => console.log(eventId, newStart)}
  onSelectEvent={(event) => console.log(event.id)}
  onViewChange={(view) => console.log(view)}
/>
```

Dates accept ISO strings or local `'YYYY-MM-DD'` with an optional `'HH:mm'` —
`'2026-11-15'`, `'2026-11-15 14:30'`, `'2026-11-15T14:30'` and
`'2026-11-15T14:30:00Z'` all work. Timezone-naive strings are treated as local
time, so `'2026-11-15'` always means November 15, never a UTC-shifted day.

## Behavior

- **Month view** — six-week grid with real date math; leading and trailing
  days from adjacent months are dimmed, today carries `aria-current="date"`
  and a highlighted day number. Chips are capped at 3 per day, then a
  `+N more` button expands that day's hidden events in a focusable panel
  below the grid.
- **Drag to reschedule** — chips use native HTML5 drag and drop and store the
  event id on `dataTransfer`. Dropping a chip on a day calls
  `onEventMove(id, newStart)` with a `"YYYY-MM-DDTHH:mm"` local timestamp that
  keeps the original time-of-day. The component never mutates `events` — apply
  the move in your state and pass the updated array back.
- **Keyboard reschedule** — focus a chip and press ←/→ to move it by a day,
  ↑/↓ by a week. Each move calls `onEventMove(id, newStart)` with the
  time-of-day preserved, focus follows the moved chip (or lands on the target
  day cell when the chip collapses behind `+N more`), and a live region
  announces it.
- **Agenda view** — every event grouped by date and sorted chronologically,
  with relative `Today`/`Tomorrow` headings.
- **Accessibility** — the toolbar is a labeled `role="group"` with an aria-live
  month title; every chip is a real button (Enter/Space activates
  `onSelectEvent`, arrow keys reschedule) with an accessible name like
  "Design review on November 15, 2026". The `+N more` panel takes focus when
  it opens, and Close or Escape returns focus to the button. View switches
  and moves are announced through a `role="status"` live region. Events with
  duplicate `id`s are reported with a console error in development.

## API

### `<CalendarScheduler />`

| Prop | Type | Default |
|---|---|---|
| `events` | `CalendarSchedulerEvent[]` | — (required) |
| `defaultView` | `'month'` \| `'agenda'` | `'month'` |
| `onViewChange` | `(view: 'month' \| 'agenda') => void` | — |
| `onEventMove` | `(eventId: string, newStart: string) => void` | — |
| `onSelectEvent` | `(event: CalendarSchedulerEvent) => void` | — |
| `className` | `string` | — |

```ts
interface CalendarSchedulerEvent {
  id: string
  title: string
  start: string
  end: string
  color?: string // CSS color used as the chip accent; text contrast stays token-driven
}
```

### Sub-components

- `<CalendarToolbar title view onPrevious onNext onToday onViewChange />` — the
  labeled navigation bar, exported for custom chrome.
- `<CalendarAgendaList events today? />` — the grouped, chronological agenda,
  exported for standalone use.

Pure helpers are exported too: `parseEventDate(input)`, `buildMonthGrid(year,
month)` and `moveEventStart(event, targetDay)`.
